Kernel and firewall hardening
"doas hardening" opens the kernel hardening menu: current values, persistent selections, Now / Selected / Apply columns, red ! for relaxed settings, yellow * for unsaved choices, and reboot for deferred changes. Pages fit the terminal. Number to change, ?N for details, f for fast tool profiles (podman/Distrobox, gdb, perf, powertop and combined debug), a to review/apply, d to reset the listed options to the dotfiles defaults. "doas hardening status" only reports. Changes are confirmed, backed up in /var/lib/hardening and rolled back on failure; interrupted transactions offer recovery on the next launch. GRUB is generated and syntax checked in a staging file, preserving every kernel image, initrd and unrelated boot argument before replacement. No automatic reboot. Selected settings survive reinstalling the dotfiles. Boot arguments show requests, not proof that the kernel or hardware applied them. Secure Boot can enforce lockdown and signatures regardless. "doas hardening fast PROFILE" goes straight to its review. Tool exceptions cover newuidmap/newgidmap (restore setuid and keep the nosuid hook from removing it) and msr (permit loading, never load or unload automatically). These exceptions survive reinstalling the dotfiles; reset to default restores their blocks. Podman checks existing subordinate UID/GID ranges; PowerTOP needs a reboot for debugfs/lockdown and Secure Boot can still enforce lockdown. Firewall, AppArmor and other module/setuid rules are outside this menu.
sysctl: /etc/sysctl.d/5{1..5}-*.conf, after the 50-default.conf of Debian that would undo some, TCP timestamps off, ARP answers only on the interface asked and no unasked ARP replies.
Firewall (nftables): drops input and forward, allows output. ICMP only errors, rate limited ping from the LAN only (the internet cannot see the machine is up, IPv6 included), neighbor discovery, router adverts, MLD. Nothing goes out that announces the machine on the LAN (mDNS, LLMNR, SSDP, NetBIOS, WS-Discovery, Steam).
SSH client: offers only configured keys, hashed known_hosts, no agent forwarding, keys stay in the agent for an hour. ~/.ssh gets mode 0700, no keys are generated.
Blocks rarely used kernel modules with a history of bugs: rds tipc atm n_hdlc n_gsm sctp appletalk psnap llc2 phonet ax25 netrom rose x25 can ieee802154 firewire floppy cramfs hfs befs qnx6 adfs ufs hpfs jfs gfs2 ocfs2 vivid kcm rxrpc nfc nilfs2 zonefs cuse userio hci_vhci, and from the list of Kicksecure dccp decnet econet ipx ksmbd affs afs ceph coda ecryptfs freevxfs jffs2 minix orangefs reiserfs romfs sysv ubifs gnss and others; mei (Intel ME), msr (fwupd reports less on the firmware, updates still work), cdrom; no PC speaker. hfsplus udf exfat ntfs3 cifs nfs thunderbolt joydev still work.
Kernel command line, active after reboot: freed memory is zeroed (a few % slower), no DMA attacks over PCI and Thunderbolt, only signed modules, no /dev/mem, kexec or hibernation, no reading of kernel memory through /proc/kcore, tracing or BPF (lockdown confidentiality), no writing into a program's memory through /proc but by a debugger; from Kicksecure no IOMMU passthrough and every device in its own IOMMU domain, KFENCE sampling heap bugs, the random pool not credited by the CPU or the bootloader alone, no writing to the disk under a mounted filesystem, TSX off (a source of CPU leaks, few programs use it). Kicksecure's other CPU mitigations are left to the kernel's defaults: the stricter ones turn off SMT or AVX and cost FPS. The recovery entry boots without them.
  ${HARDEN_CMDLINE[*]}
systemd sandbox on top of Debian's units: NetworkManager (no new privileges, private /tmp, no clock or kernel log), dnscrypt-proxy (no capabilities, read-only system, private devices, system call filter), bluetoothd (no kernel modules, only bluetooth sockets), wpa_supplicant (it parses what comes over the air as root: only its capabilities, read-only system and home, system call filter), and the watchdog, usbguard-notify and journal-prune of the dotfiles.
New machine ID at every boot, so apps cannot track this machine by it: /etc/machine-id is empty on disk, systemd puts a random one over it in RAM and never saves it. The journals of the old IDs are kept up to 400 MB.
fstab: /boot and /boot/efi nosuid,nodev,noexec and readable by root only, /tmp a nosuid,nodev tmpfs unless a partition, /home nosuid,nodev.
Core dumps: a dump is the memory of the program, keys and passwords included. Only the one of g0wm is kept (~/.local/state/g0wm, for debugging it), the others are dropped (core-keep).
/proc, after reboot (fstab): the daemons' users see only their own processes. Group proc sees all: polkitd, rtkit, systemd-logind, $TUSER (the polkit agent needs it).
No setuid on su pkexec passwd chsh chfn chage expiry gpasswd newgrp sg mount umount newuidmap newgidmap fusermount (the old one, fusermount3 stays for the FUSE mounts of the desktop) pppd (NetworkManager runs it as root) ssh-keysign wall write Xorg.wrap firejail lxc-user-nic qemu-bridge-helper spice-client-glib-usb-acl-helper: doas does it ('doas passwd $TUSER').
No file capabilities on cdrecord readcd cdda2wav (dac_override and sys_admin on programs anyone can run).
  dpkg-statoverride keeps the modes across updates; apt runs nosuid after each run, for what a new package brings.
